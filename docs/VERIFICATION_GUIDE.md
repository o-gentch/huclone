# Как запустить и проверить всё в браузере

Руководство для локальной проверки: от подготовки машины до сценария «загрузил видео → подтвердил спикера → спросил в чате → получил оглавление книги». Реализация выполнена по `docs/VIDEO_TECH_PLAN.md`; детали деплоя — в `docs/SETUP_CHECKLIST.md`.

## 1. Что нужно подготовить (один раз)

| Что | Зачем | Как |
|---|---|---|
| **Postgres 17 с pgvector** | У вас по умолчанию запущен Postgres 14, а pgvector собран только под 17/18 — на 14-м приложение не стартует | См. §2 |
| **ffmpeg** | Извлекает аудио из видео. Сейчас на машине **не установлен** — без него загрузка видео упадёт на первом этапе | `brew install ffmpeg` |
| **Ключ OpenAI** | Чат, эмбеддинги, карта личности, резюме, дерево тем | Уже лежит в `config/credentials.yml.enc` (проверено: ключ есть; нужен `config/master.key`, он на месте) |
| **Ключ AssemblyAI** | Распознавание речи и разделение по спикерам. **Сейчас не настроен** | См. §3 |
| (Только для деплоя) S3-бакет | Хранить большие файлы мимо Rails | См. `docs/SETUP_CHECKLIST.md`. Для локальной проверки **не нужен** |

## 2. Postgres 17 с pgvector

Postgres 17 у вас уже установлен через Homebrew, данные лежат в `/usr/local/var/postgresql@17`. Запускайте его на отдельном порту, чтобы не трогать остальные проекты (они используют 14-й):

```bash
LC_ALL=en_US.UTF-8 /usr/local/opt/postgresql@17/bin/pg_ctl -D /usr/local/var/postgresql@17 -o "-p 5433 -k /tmp" -l /tmp/pg17.log start
```

Без `LC_ALL` сервер не стартует (ошибка про локаль). Проверка:

```bash
psql -h localhost -p 5433 -d postgres -c "select version()"
```

Дальше во **всех** командах проекта задавайте окружение (удобно положить в отдельный терминал):

```bash
export LC_ALL=en_US.UTF-8 PGPORT=5433 PGHOST=localhost
```

## 3. Ключ AssemblyAI

1. Зарегистрируйтесь на https://www.assemblyai.com и подтвердите почту.
2. В дашборде найдите **API Key** (раздел Dashboard / API keys) и скопируйте.
3. Пополните баланс (Pay-as-you-go). Для проверки хватит нескольких долларов: ориентир ≈ $0.06 за 20-минутное видео (≈ $0.17 за час аудио, с диаризацией).
4. Передайте ключ приложению **одним из способов**:
   - переменной окружения перед запуском: `export ASSEMBLYAI_API_KEY=ваш_ключ`
   - или в зашифрованных credentials: `bin/rails credentials:edit` и добавьте блок
     ```yaml
     assemblyai:
       api_key: ваш_ключ
     ```
     (рядом уже есть `openai:` — структура такая же).

## 4. Запуск приложения

```bash
export LC_ALL=en_US.UTF-8 PGPORT=5433 PGHOST=localhost
bundle install
bin/rails db:prepare          # создаёт/мигрирует базы primary, queue, cable
bin/rails "users:create[you@example.com,придумайте-пароль]"
bin/dev                       # web + tailwind watcher + воркер очередей
```

**Важно запускать именно `bin/dev`, а не `bin/rails server`:**
- без воркера (`solid_queue`) джобы не выполняются — запись будет вечно «извлекаем звук», а чат не ответит;
- без `tailwindcss:watch` не собираются стили новых экранов (при проверке на голом `rails s` у меня на странице загрузки были видны скрытые элементы и растянутые бейджи — это устаревший CSS, не баг кода).

Откройте http://localhost:3000, войдите созданным пользователем. Если у вас уже была персона без владельца, команда `users:create` привяжет её к новому пользователю; иначе на первом экране создайте персону («Создать аватара»).

## 5. Тестовые материалы

- Видео/аудио **1–3 минуты**, где разговаривают **двое** (один задаёт вопрос, второй отвечает), по-русски. Подойдёт любое интервью/подкаст-отрывок. Форматы: mp4, mov, webm, mkv, mp3, m4a, wav, ogg. Размер без S3 — до 500 МБ.
- Пара коротких текстов-постов (для проверки, что письменный режим не сломался).
- Второй файл с другим содержанием — для проверки дерева тем (нужны 2–3 записи).

Стоимость одной такой проверки — центы (ASR + LLM).

## 6. Сценарий проверки

### А. Загрузка и расшифровка
1. Вкладка **«Видео» → «Загрузить запись»**. Укажите название, выберите файл, при желании «Сколько людей говорит» = 2. Нажмите «Загрузить».
   - Ожидаем: прогресс-бар, переход на страницу записи со статусом «Извлекаем звук…».
2. Не обновляя страницу, наблюдайте смену статусов: «извлекаем звук» → «расшифровываем» → «нужно выбрать спикера» (занимает 1–5 минут).
   - Если запись «Ошибка»: прочитайте сообщение на странице. Типичные причины: нет ffmpeg, нет `ASSEMBLYAI_API_KEY`, неверный ключ, пустая речь. После исправления нажмите «Повторить».
3. Повторно загрузите тот же файл — должно появиться предупреждение о дубле с кнопкой «Всё равно загрузить».

### Б. Выбор спикера
4. На странице записи у каждого спикера есть доля речи, число слов, фрагменты. Нажмите **«▶ 0:12»** у фрагмента — должен проиграться именно этот кусок.
5. Выберите «Это я» (предвыбран тот, кто говорит больше). Если голоса перепутаны, проверьте блок «Перераспознать» с указанием числа говорящих.
6. Нажмите **«Подтвердить»**. Ожидаем: статус «подтверждено», ниже расшифровка с таймкодами и цветом по спикерам.

### В. Знания из видео
7. Откройте **http://localhost:3000/jobs** (Mission Control): должны отработать `ProcessRecordingJob` → `ProcessContentJob`, затем `BuildPersonalityMapJob` (дебаунс ~2 минуты). Красных (failed) джобов быть не должно.
8. Вкладка **«Чат» → «Новый разговор»**, режим «По материалам». Спросите по содержанию видео: «О чём говорил автор про …?».
   - Ожидаем: ответ с пометкой источника («из выступления …, мм:сс») и ссылки под сообщением; ссылка ведёт на запись.
9. Запишите вторую-третью запись (повторите А–Б).

### Г. Темы и «книга»
10. Вкладка **«Темы»** (после 2–3 записей; при необходимости «Пересобрать»): дерево тем с резюме и ссылками. «Экспорт в Markdown» скачивает файл.
11. В чате переключитесь на **«📖 Книга»** и напишите: «Составь оглавление книги по всем выступлениям» → оглавление из дерева. Затем «Раскрой главу …» (название из оглавления).
12. Запрос «Напиши пост про …» в обычном режиме — должен использовать письменный голос и посты-образцы.

### Д. Безопасность и управление
13. Откройте ссылку аудио записи (`/personas/ID/recordings/ID/audio`) в приватном окне — должен быть редирект на вход.
14. Удалите запись («×» в списке) — запись, её фрагменты и расшифровка исчезают.
15. Выйдите («Выйти») и убедитесь, что без входа ни одна страница не открывается.

## 7. Если что-то не работает

| Симптом | Причина / что делать |
|---|---|
| `could not access file "$libdir/vector"` при `db:prepare` | Вы подключены к Postgres 14. Проверьте `PGPORT=5433 PGHOST=localhost` |
| Запись вечно «Извлекаем звук» | Не запущен воркер (используйте `bin/dev`) или не установлен ffmpeg |
| «Не задан ASSEMBLYAI_API_KEY» | Не задан ключ (§3). После этого — «Повторить» |
| Ошибка от AssemblyAI про параметры (400) | См. «Известные риски» ниже; текст ошибки показывается на странице записи |
| Чат не отвечает / «Произошла ошибка» | Смотрите `/jobs` → `ChatResponseJob` и логи; проверьте OpenAI-ключ и баланс |
| Ссылки/цитаты не появились | Записи ещё обрабатываются: смотрите `/jobs`; чанки создаются после `ProcessContentJob` |
| Стили «поехали» | Запущен не `bin/dev` (нет tailwind watcher) |

## 8. Известные риски (что я не мог проверить)

- **Реальный AssemblyAI ни разу не вызывался.** В запросе используется параметр `speech_models: ["universal-2"]`, `speaker_labels` и `language_code: "ru"`. Если API ответит 400 про параметры — в `app/services/transcription/assembly_ai.rb` поправьте имя/значение модели по актуальной документации. Особенно проверьте качество диаризации на русском.
- **Реальный ffmpeg не запускался** (на машине его нет), хотя тест на него написан.
- **S3 не проверялся**; локально он не нужен.
- Качество LLM-этапов (очистка речи, резюме, названия тем, `spoken_style`) проверено только на фейках — на реальных записях возможна подстройка промптов и порогов.
- Для деплоя остаётся всё из `docs/SETUP_CHECKLIST.md` (сервер, S3, CORS, секреты Kamal).
