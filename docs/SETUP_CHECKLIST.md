# Что нужно сделать вручную (Задача 1: видео → расшифровка → выбор спикера)

Код, миграции, тесты и конфигурация готовы. Ниже — только то, что требует ваших действий.

## 1. Регистрация в сервисах
1. **AssemblyAI** (https://www.assemblyai.com) — создайте аккаунт, пополните баланс (Pay-as-you-go хватает; ориентир: ≈ $0.15/ч Universal-2 + $0.02/ч диаризация, т.е. ≈ $0.06 за 20-минутное видео). Включать дополнительные опции не нужно.
2. **S3-совместимое хранилище** (рекомендуется для продакшена; AWS S3, Yandex Object Storage, Cloudflare R2, Selectel и т.п.) — создайте **приватный** бакет и ключ доступа с правами чтения/записи/удаления только на этот бакет. Без S3 работает локальный диск, но файлы ограничены 500 МБ и загружаются через Puma.

## 2. Ключи и секреты
Через ENV (предпочтительно в `.kamal/secrets`) или `bin/rails credentials:edit`:

```yaml
# bin/rails credentials:edit — структура без значений
openai:
  access_token:
assemblyai:
  api_key:
```

ENV-имена: `ASSEMBLYAI_API_KEY`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (секретные); `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` (для не-AWS), `S3_FORCE_PATH_STYLE` (`true` для MinIO и некоторых провайдеров) — несекретные.

## 3. `config/deploy.yml` и `.kamal/secrets`
```yaml
# config/deploy.yml
servers:
  web:
    - <IP_СЕРВЕРА>
registry:
  server: <реестр образов>
  username: <логин>
  password:
    - KAMAL_REGISTRY_PASSWORD
env:
  secret:
    - RAILS_MASTER_KEY
    - ASSEMBLYAI_API_KEY
    - S3_ACCESS_KEY_ID
    - S3_SECRET_ACCESS_KEY
  clear:
    SOLID_QUEUE_IN_PUMA: true
    ACTIVE_STORAGE_SERVICE: s3          # или local
    S3_BUCKET: <имя бакета>
    S3_REGION: <регион>
    S3_ENDPOINT: <https://… только для не-AWS>
    RECORDING_MINUTES_QUOTA: 300
    TRANSCRIPTION_MAX_CONCURRENT: 5
```
```bash
# .kamal/secrets
ASSEMBLYAI_API_KEY=$ASSEMBLYAI_API_KEY
S3_ACCESS_KEY_ID=$S3_ACCESS_KEY_ID
S3_SECRET_ACCESS_KEY=$S3_SECRET_ACCESS_KEY
```

**CORS бакета для прямой загрузки из браузера** (подставьте свой домен):
```json
[
  {
    "AllowedOrigins": ["https://ВАШ-ДОМЕН"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type", "Content-MD5", "Content-Disposition"],
    "ExposeHeaders": ["Origin", "Content-Type", "Content-MD5", "Content-Disposition"],
    "MaxAgeSeconds": 3600
  }
]
```
(в консоли AWS — вкладка Permissions → CORS; у других провайдеров формат аналогичный).

## 4. Сервер
- **ffmpeg/ffprobe** уже ставятся в образ (`Dockerfile`), на сервере ничего ставить не нужно. Для локальной разработки: `brew install ffmpeg`.
- **Диск:** при `ACTIVE_STORAGE_SERVICE=local` — volume `huclone_storage:/rails/storage` (уже есть в `deploy.yml`), запас под файлы; для обработки нужно временное место ≈ 2× размера файла + 200 МБ (проверяется перед стартом).
- **Очереди:** очередь `media` — один процесс (ffmpeg нагружает CPU), не увеличивайте `processes` для неё. При `SOLID_QUEUE_IN_PUMA` воркеры живут в том же контейнере — на маленьком сервере следите за CPU.
- **Лимит тела запроса у прокси:** при S3 direct upload не затрагивается. При локальном диске файл идёт через Thruster/Puma — убедитесь, что внешний прокси (если есть) разрешает тело ≥ 500 МБ.

## 5. Миграции и команды при деплое
```bash
bin/rails db:migrate      # создаёт таблицы Active Storage, recordings, speakers, utterances, usage_events
```
Новых пользователей создаёт та же команда, что и раньше: `bin/rails "users:create[email,пароль]"`. Периодическая задача `StuckRecordingsWatchdogJob` подхватывается автоматически из `config/recurring.yml`.

## 6. Проверка, что всё работает (5–7 шагов)
1. Войдите, откройте «Видео» → «Загрузить запись».
2. Выберите короткий файл (1–2 минуты с разговором двух людей), нажмите «Загрузить» — виден прогресс-бар.
3. На странице записи статус сменится: «загружено» → «извлекаем звук» → «расшифровываем» (без обновления страницы).
4. Через несколько минут статус «нужно выбрать спикера»: у каждого спикера доля речи, фрагменты и кнопка «▶».
5. Нажмите «▶» — играет нужный фрагмент; выберите «Это я», при желании задайте имена, нажмите «Подтвердить».
6. Статус «подтверждено», ниже видна расшифровка с таймкодами.
7. Проверьте защиту: откройте ссылку аудио (`/personas/…/recordings/…/audio`) в приватном окне — должен быть редирект на вход. Загрузите тот же файл ещё раз — должно прийти предупреждение о дубле.

## 7. Что осталось неполным или непроверенным
- **Реальный ASR не прогонялся:** у меня нет ключа AssemblyAI; адаптер проверен только на заглушках HTTP по документации (параметры `speech_models: ["universal-2"]`, `speaker_labels`, `speakers_expected`). Возможно, придётся поправить параметры при первом реальном запуске — проверьте именно диаризацию на русском (в документации прямого подтверждения для `ru` + `speaker_labels` нет).
- **ffmpeg не установлен на машине разработки**, поэтому тест извлечения аудио и тест «битый файл» были **пропущены** локально (запустятся там, где ffmpeg есть, в т.ч. в CI, если поставить пакет). Фактическую команду ffmpeg проверьте на первом реальном файле.
- **Браузерная часть (прогресс-бар, прослушивание фрагментов, потоковое обновление статуса) не проверялась в живом браузере** — только отрисовка страниц и контроллеры в тестах.
- **S3 не проверялся** (нет бакета): конфиг в `config/storage.yml` и гем `aws-sdk-s3` добавлены, CORS — по документации Rails.
- Сырой ответ провайдера (с пословными таймкодами) **не сохраняется** — только нормализованные реплики (§5, п.11); пересчёт без повторной оплаты невозможен.
- Скачивание аудио реализовано через `send_data` (файл ≤ ~20 МБ на час), не стриминг.
- Подключение к карте личности и поиску — Задача 2: `Recordings::Pipeline.after_confirm` пока ничего не делает.
- `bin/brakeman` в репозитории требует последнюю версию гема (`--ensure-latest`) и падает с кодом 5 на 8.0.4 vs 8.1.0; сканирование `bundle exec brakeman` — 0 предупреждений.
